# 测量速度：开发检查、优化边界与验收

更新：2026-10-16。适用于本项目所有仪器模块及 Combination。

新功能、重构和集成必须检查本文件，交付时说明耗时影响。目标是缩短取得
**有效且可审计结果**的总时间；通信失败、无效点、重新判稳和重测均计入成本。
功能测试通过和实机提速通过必须分开记录。

## 1. 本次实测发现

基线版本为 `7efdc1c`。2026-10-16 的一次 NKT/PM100D、6221 串口转发、
2182A CH2 无激励扫描，前 16 个已采集条件包含 48 次正式电压读数。
固定带宽、功率容差、积分时间和采样数只描述这一组证据，不是新默认值。

| 阶段 | 平均每个条件 | 说明 |
|---|---:|---|
| 调光后的电学准备及核对 | 约 11.7 s | 包含重复完整设置查询 |
| 3 次电压读取及前后核对 | 约 46.1 s | `READ?` 单次往返本身约 0.212 s |
| 功率调节和判稳 | 约 7.5 s | 混合暗/亮平均；亮点平均 8.561 s |
| 正式 PM 采样及相关保护 | 约 3.1 s | 保留新鲜读数和状态检查 |
| 光学准备 | 约 0.7 s | NKT 已读回相同则不重复写 |
| 其他 | 约 3.0 s | 其他通信、间隔和记录等余项 |
| 总计 | 72.062 s | 亮点单独平均 73.088 s |

完整 2182A 核对包含身份与 22 项设置，共 23 条下游查询。原来正常的
单电学坐标、三次读数功率点，约有 15 轮完整核对：准备阶段 3 轮，
每个读数周围 4 轮。采集函数内的单次读取流程平均 7.832 s。

串口查询固定先睡眠 0.1 s。快照中的 5,832 次完整转发均在第一次轮询
取得应答，请求睡眠合计 583.2 s；这不能证明响应在更早时刻已经就绪。
显式光学/电学 settle 请求睡眠合计为零，已有通信已覆盖所需等待。
判稳完成至首个正式功率检查仍相隔约 15.992 s。

同一轮后来在 594.4 nm / 75 µW 点因功率越过容差下沿被拒绝。短窗口内
功率持续下降，仍可能同时满足宽目标容差与峰峰值限制。因此实际吞吐量
必须计入漂移失败和重跑，不能仅统计成功点或人为扩大容差后的速度。

只读证据位于 ignored `run_data/resume562_20261016T100955Z/`：
`speed-breakdown.json`、`timing-statistics.json`、`latest-failure-summary.json`。
实机原始文件、站点地址、用户本地 TOML 和实验数据不得提交。

## 2. 本次实现与证据生命周期

### 2.1 被动电压探测器：共享同一采样边界的完整核对

现有 `HardwareElectrical`、`Voltmeter2182` 和 `PhotoresponseRunner` 继续共用，
不另建平行测量入口。

```text
光学准备／PM 判稳（电学激励关闭）
  -> 完整核对 2182A 设置，重新确认源／转发主机安全
  -> 电学 prepare，保留源的 ramp、限幅、读回与等待
  -> 对每次正式读数：
       光学和源安全检查 -> PM before
       -> 完整核对 2182A -> 新鲜 READ? -> 完整核对 2182A
       -> PM after -> 光学和源安全检查
       -> 保存本次 READ 对应的 before/after 设置证据及独立时间戳
```

外层采样边界不再额外重复一套完整被动探测器设置查询。它们持续查询源的
输出、设定、armed、compliance 和相关状态；从**这一次 READ**取得探测器
before/after 证据。没有跨读数缓存、固定时间有效期或全局“已检查”标志。
未完成 READ 的失败尝试明确记录 detector verification 尚未发生。

正常单电学坐标、三次读数功率点变为 1 + 2×3 = **7 轮**完整核对，
不含首次配置等一次性开销。长时间调光后的一次完整核对仍然存在。
身份、通道、量程、NPLC、触发、扫描、滤波和数学处理项目都保留。

能输出的 2400 仍执行完整状态检查；6221 激励的 ramp、启用后保护核对、
关闭和最终清理不省略。SMU 和环境转场仍执行原验证。不得把本次被动
2182A 的证据复用直接套用到能给样品施加电压／电流的设备。

### 2.2 串口轮询

`Serial2182Transport` 默认等待仍为已验证的 100 ms。本轮撤回未经实机验证的
20 ms 默认值；显式注入 20 ms 的离线实验仍保留 20/40/80/100 ms 退避。
这不是新的 TOML 字段，不改变用户配置及其来源。

- SEND 和全部 ENTER 轮询始终持有同一个共享主机锁，禁止并发混读。
- 一条查询只 SEND 一次，空响应只继续 ENTER，不重发命令。
- 使用同一单调时钟，从 SEND 前开始计算期限；等待不超过剩余预算。
- 每次 I/O 后再检查期限，非空但迟到的响应也拒绝。
- 保留实际响应、请求等待和失败耗时；超时／未知响应使会话失效，禁止
  后续查询把迟到数据当成新应答。底层同步 VISA I/O 的自身超时仍然适用，
  不宣称 Python 能中断尚未返回的底层调用。
- 不清总线、不 reset、不消费额外状态锁存来提高通过率。

20 ms 是待实机对照的实现参数，不是所有固件都已验收的响应时间。

### 2.3 离线命令预算对照

同一组生产路径 fakes：固定波长 CLD、dark + 两个亮点、每点 3 次电压读取，
采样数、功率质量参数及差分结果保持一致。回复在首次轮询即就绪：

| 方案 | 下游查询 | 完整核对轮数（含首次设置） | fake-clock 耗时 |
|---|---:|---:|---:|
| 原核对边界，100 ms 轮询 | 1,106 | 46 | 111.01 s |
| 共享核对边界，100 ms 轮询 | 554 | 22 | 55.81 s |
| 共享核对边界，20 ms 起始轮询 | 554 | 22 | 11.49 s |

三种方案均有 9 次正式 READ、3 个接受条件及独立激光关闭／电学安全清理。
最新全量主机事务（含SEND/ENTER及原生查询）为4,359→3,165，PM READ均37次。
这个模型不含实机积分、GPIB/VISA 延迟和真实光学响应，不能用其加速比承诺实机速度。
测试保留 100 ms 基线，另测空响应退避、迟到响应、期限截断及设置漂移。
证据在 ignored `run_data/speed_optimization_20261016/fake-benchmark.json`。

## 3. 每次开发必须检查的项目

### 3.1 设置和核对

- 区分首次连接、轴点进入、实际调档、正式采样边界和最终清理。
- 写命令尽量读后比较，仅在实际变化时写；有意重复写必须说明设备原因。
- 对每个条件列出完整核对轮数和每轮查询数量，排查编排层与设备层重复。
- 复用证据必须说明所属会话、实际采样、前后边界和采集时间。不得用旧源
  状态替代新鲜输出／故障读回，不得用 `FETCh?` 替代正式新采集。
- 优先复用公共 driver 和接口，在能力边界保留分支差异。

### 3.2 轴点与判稳

- 温度、磁场判稳在外层轴点进入时完成，再执行全部内层测量；内层保留
  实际读回、质量标记及故障保护。回访、重复、新尝试和断点恢复重新判稳。
- 光学功率是电学扫描外层时，先稳定光，再核对电学并启用激励／采集。
- 暗态规则、匹配坐标和基线年龄不因提速改变；一个暗点不能冒充多个独立重复。
- 每次实际调光后重新建立功率稳定证明；正式窗口冻结执行器，保留前后 PM 检查。
- 容差、噪声、积分时间和窗口长度是测量质量参数，不能静默放宽来宣称提速。

### 3.3 等待和通信

- 用单调时钟计算最后一次相关实际变化后的剩余等待，扣除其它工作已经
  经过的时间。不要重复追加固定等待或把同一次变化重复计时。
- 明确区分最低响应等待、稳定窗口、轮询间隔、仪器积分、软件 I/O 和审计开销。
- 共享 GPIB/串口按响应所有权串行操作；不可用线程并发绕过单总线瓶颈。
- 独立总线也只有在不破坏采样先后与安全屏障时才能重叠操作。先量化收益。
- 超时、半包、无效读数和记录失败的清理路径同样受测试，不以自动重试掩盖不确定通信。

### 3.4 记录与统计

- 保存单调起止时刻、I/O 命令数量、请求睡眠、调节次数及关键前后读回。
- 同时报告完整点周期和各阶段耗时；父阶段包含子阶段，求和时使用互斥耗时，
  防止重复计入 snapshot、guard 和采集中的嵌套操作。
- 区分底层 I/O 时间与 JSON／SQLite／回调开销；记录未确认的余项。
- 监控／绘图只读文件，不引入新的仪器查询。读取活跃 SQLite 使用短只读事务，
  读取后关闭连接，再在本地执行压缩、计算和绘图。
- rejected、invalid、transition、cleanup 原始记录和配置来源完整保留。
  不删除审计、关闭持久化或提升部分失败结果来换速度。

## 4. 验收与交付

1. 先用 fake clock／资源复现冗余，记录基线调用数量和阶段时间。
2. 增加命令预算和故障测试：调光后改设置、READ 期间改设置、活动源／unsafe、
   overload、空响应、延迟／迟到响应、超时、审计失败和独立清理。
3. 对相同功率／波长／偏置网格保持采样数、NPLC、容差、暗态规则一致，比较
   原始读数、差分、有效性和 cleanup；完整回归必须通过。
4. 实机对照需要明确授权，并确认没有正在运行的扫描或其它仪器占用。
   活跃扫描期间不得部署、修改其配置、打开第二个仪器会话或做性能压力测试。
5. 小规模实机先比较相同参数下的点周期、查询数、实际积分、调节次数、
   功率漂移／拒绝率和最后状态，再决定是否推广到全网格。
6. 在阶段／交接文档分别写出：离线验证、实机响应验证、部署及扫描启动状态。
   fake-clock 的加速比不能当成实机加速比；硬件等待和噪声可能改变结果。

后续交付至少回答：**每点发送多少查询／写入？在哪些边界必须判稳？哪些等待
可以共享？有哪些重复证据？点周期与失败重跑成本是多少？有哪些实机未验证假设？**

## 5. 本轮稳定性与有限恢复

见 [POWER_STABILITY_OPTIMIZATION.md](POWER_STABILITY_OPTIMIZATION.md)。本轮已显式
分开调光中心精度、相对/绝对波动及漂移趋势、正式验收容差；dark-first 支持
普通功率偏差的有限恢复与完整窗口重测。失败窗口、暗态来源、审计和清理都保留。
已通过离线回归，真实光学响应、参数选择和实机速度收益须单独验收。

调光后完整电学核对保持一次，随后新鲜 PM 屏障检查；正式读取仍有前后功率
检查，不使用陈旧证明直接启动。no-excitation 转发主机还明确核对电流设定零。
普通光学偏差不等于无信号、保护、通信不明或清理失败，后几类不能重试加输出。
低功率实测噪声、5s/2s及5%/10%的适用性、受控实机A/B与20ms轮询仍需验证。
